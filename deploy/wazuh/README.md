# NambaDrive audit collection

Install the official Wazuh agent on each application/worker host and enroll it in the organization's protected Wazuh manager using verified manager identity. Merge `agent.conf` into the agent's central group configuration. The host path must be the same audit volume used by backend and workers. Configure Wazuh's log collector account/group with read-only access; application writes use owner-only write permission (0640 or stricter). Never expose Wazuh, storage or database management ports to user networks.

Copy `nambadrive_rules.xml` to `/var/ossec/etc/rules/` on the manager (not its vendor-managed ruleset directory). Validate with `wazuh-logtest`, then restart the manager to activate rules. Reserve rule IDs 110000–110014 or deliberately remap conflicting local IDs with matching fixture updates. Enable archives/index retention appropriate to organization policy, monitor collector lag/disconnection and disk pressure, and retain an independently protected off-host copy. The application's audit file is append-only through its API, not magically immutable against host root or stolen filesystem credentials. Wazuh's external retention and restricted host administration form the tamper-detection boundary.

CI `scripts/test-wazuh.sh` runs a disposable Wazuh manager 4.14.8 with no published ports, using the actual JSON decoder and `wazuh-logtest -U` for the bundled synthetic fixtures. Runtime engine tests do not prove host-agent enrollment, actual network delivery or production retention. Validate those after configuring the target environment. Rules emit higher-severity alerts for malware, Break Glass and governance changes, and correlate repeated authentication failures/access denials or high download activity. Thresholds are initial detection settings, not automatic access revocation.

## Rotation and recovery

Precreate the audit directory and file for the application UID, mode 0750 directory / 0640 file, with a collector read group. Existing world-readable/writable logs must be fixed by an operator before startup; the writer fails closed instead of silently accepting unsafe permissions. Mount this directory separately from disposable container filesystems. Do not use copytruncate. Rotate by an authorized host process renaming the current file and creating the new file with the same owner/group/mode; each append reopens the current path. Preserve and collect rotated segments before cold archival; the application has no log editing/deletion route. Collector permissions, rotation and cold retention are deployment controls and must be exercised on the target host.

If a write stops mid-record, further writes fail closed because the segment does not end in a newline. Preserve the incomplete segment as forensic evidence, rotate to a new correctly owned segment and reconcile the affected operation using PostgreSQL and correlation IDs. Never truncate or rewrite the evidence to make a check pass. A successful fsync followed by a database failure can leave an audited attempted change whose database transaction rolled back. Audit entries emitted before commit are evidence of authorized intent; compare state when determining committed outcome.
