# Phase 6 — upload quarantine and ClamAV

`POST /api/v1/documents/upload?parent_id=<uuid>&filename=<name>` receives raw binary bytes with a valid application session and CSRF token. AuthorizationService checks CREATE on the parent before accepting content and again under the parent lock. Filenames and server-side content detection enforce the approved formats. The browser receives only document/version IDs, SHA-256 and PENDING status. The UI provides a file upload form and explains the pending scan.

Migration 0006 adds immutable-version metadata and a durable pending queue. The object is first written to the quarantine bucket, the resource remains QUARANTINED and all content/metadata access is denied by AuthorizationService. `python -m app.documents.worker` claims pending versions using PostgreSQL `FOR UPDATE SKIP LOCKED`, checks uploader rights again, verifies quarantined bytes against DB SHA-256, sends ClamAV INSTREAM, and activates only after exact `stream: OK`. Malware stays inaccessible. Unknown replies, scan limits, timeouts, unavailable AV/storage, and failed audit all fail closed. A failed item has a five-minute retry delay so it cannot starve other uploads. A DB rollback after successful object promotion is reconciled by checking immutable object metadata, never overwriting it.

ZIP inspection bounds entries (10,000), total expansion (upload limit), ratio (100:1), rejects traversal, symlinks, encryption and nested archives, and reads every member to verify CRC. OOXML requires its expected container members and rejects VBA containers. Text parsing is UTF-8, max 32 MiB; XML uses defusedxml with DTD/entities/external references forbidden. Binary upload default is 500 MiB. These explicit format limits are conservative rejections, not AV bypasses.

ClamAV deployment MUST use the supplied `deploy/aio/clamav/clamd.conf`: AlertExceedsMax and AlertEncrypted prevent unscanned or encrypted files being reported clean; scan limits cover the default upload size. Increase scanner and proxy limits together when increasing the application limit. Keep clamd private, run freshclam with official databases, and run the worker with backend DB/storage/audit configuration. No clamd or SeaweedFS port belongs on the user network. Full container topology/hardening is completed in subsequent deployment phases.

Quarantine copies are retained for governed cleanup, including failures/orphans. This phase does not expose physical delete. Later retention/purge work must account for both buckets.

Validation includes filename/MIME/archive/XML abuse, CSRF/IDOR, owner denial while quarantined, malware/outage/checksum failure, revoked-uploader rejection, and audit rollback/retry. Real ClamAV is additionally tested with clean text and EICAR. CI uses the actual clamd engine with an isolated deterministic EICAR-only test signature; production must never use that test database. Local runtime validation uses official freshclam databases. External Authentik and container deployment remain separate acceptance checks.
