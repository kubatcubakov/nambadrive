# Phase 21 — security hardening and complete deployment profiles

Central AuthorizationService now refreshes resource ancestors, organization status, owners, role bindings, ACL entries, manager grants, hard policies and historical version policy inputs on every evaluation. A previously loaded ORM identity map cannot preserve an earlier ALLOW after revocation. Default DENY, approved grant evaluation order and non-bypassable Legal Hold/retention remain unchanged. Critical mutations continue using governance locks and durable audit.

OIDC redirects reject external origins, encoded slashes/backslashes and control characters. Discovery/JWKS caches are scoped by immutable configured issuer/client; discovery endpoints must retain the configured provider origin and verified issuer. Code/JWKS/discovery requests reject redirects/environment proxies and explicitly verify configured CA trust. Multi-audience tokens require the correct authorized party. Production startup fails on insecure cookies, missing OIDC/HTTPS endpoints, development credentials, non-verified PostgreSQL TLS, weak/shared Office keys, missing search authentication/CA or weak SCIM capability. Private mounted scalar settings fail on symlink/permissions/unknown names. Errors hide input credentials; DB/cache/client/CSRF settings are excluded from representations.

Protected API responses disable caching and active content, forbid framing, suppress referrers and expose correlation IDs. Production docs/OpenAPI are disabled and Host is validated. HTTP client/SDK wire logging is suppressed to prevent capability URLs/request payloads being logged. App/gateway access logs never record raw OIDC codes/session/editor/share capabilities; controlled durable audit remains enabled.

Complete AIO and per-host PROD-COMPACT/PROD-DISTRIBUTED Compose definitions provide all six durable workers, PostgreSQL 17+WAL, private Redis, isolated Tika/ClamAV, authenticated OpenSearch, SeaweedFS, signed Office and separate public/SCIM/editor/storage gateways. Three production masters, two volume servers and replication 001 use the same application/schema. Private service bindings require authenticated host transport/firewall preflight. TLS/mTLS keys and credentials are private file mounts, not source/environment examples. Containers have resource limits, no-new-privileges, dropped capabilities and explicit vendor startup exceptions. Application/frontend/parser are non-root with read-only filesystems. Images and runtime dependencies are pinned; frontend builds use npm ci. S3/cache/parser/AV/database endpoints remain unavailable to user networks.

The pinned Office image's vendor startup normally writes the same JWT secret into outbox. The derived build patches only the reviewed outbox assignment and fails if vendor layout changes. It preserves distinct browser/inbox versus outbox keys and enabled checks. Unstructured vendor request logs are disabled; application audit and service health remain available. See the common deployment runbook for ownership, trust chains, least-privileged database/search roles, bootstrap and runtime boundaries.

No migration is needed; upgrade/check/downgrade/upgrade on real PG17 is still required. Positive/negative hardening tests simulate out-of-band revocations against cached ORM objects, reject malicious OIDC metadata/redirects, verify file permissions/secret-safe errors and transport log suppression. Local/PG/CI evidence is recorded in CURRENT_STATE when gates finish. CI checks every Compose configuration, builds actual backend/frontend/Tika/PostgreSQL/Office derivatives and performs actual container vulnerability scanning with no Critical allowlist. High findings remain explicit review artifacts; no authorization bypass can be accepted. ZAP/performance/final acceptance belong to Phase 22 and cannot begin until this phase's gates are green.

Real multi-host TLS/firewall/replication failover and Authentik/live Office acceptance remain infrastructure/UAT requirements, never inferred from YAML or image builds. No production deployment or merge was performed. Container remediation checkpoint (initial Phase 21 scan blocked advancement):
- All deployed Nginx gateways/frontend use the patched stable Alpine derivative; system packages are updated during the build and the entire resulting image is scanned.
- PostgreSQL stays on 17.11. The obsolete Go-based `gosu` UID-drop helper is replaced by Alpine `su-exec` through a compatible wrapper; CI verifies the UID drop and actual database startup.
- ONLYOFFICE retains the official application package and signed integration. OS updates and removal of unused kernel development headers are performed through APT, with an installed-package check.
- Apache Tika 4.1.0 is downloaded as its official ZIP distribution with pinned SHA-512, including its patched CXF/Jetty libraries. The config disables text recognizers (OCR/enrichment), per-request configuration and pipes endpoints; the parser network has no Internet egress. Actual format extraction is regression tested.
- Redis and OpenSearch OS dependencies are updated in deployed derivatives. Backend runtime build tooling is removed after installing the application; runtime dependencies remain pinned.
- Backup recovery waits for required object metadata to become available before performing the unchanged full-content SHA verification. TCP listener readiness alone is insufficient.
No CVE exceptions or ignore lists are introduced. The updated CI scan must pass before Phase 22 starts.

High review follow-up: Amazon Linux 2023 locks DNF to the image's historical repository release; ordinary `dnf upgrade` found no updates. The OpenSearch derivative explicitly updates from the current official AL2023 repository before scanning. ClamAV's Alpine PCRE2 is likewise updated in its deployed derivative. Backend remaining OS findings concern local mount/namespace/home-management tools or terminal/Perl libraries: the app runs UID 10001 with no capabilities, no new privileges, a read-only root and no host mounts/shell API. These are visible vendor findings, not a claim of zero High vulnerabilities. OpenSearch's bundled Jackson/JLine DoS findings remain under resource limits and private authenticated access; they are not authorization bypasses. Runtime/provider acceptance remains mandatory.

Base image digests and application dependency locks are fixed. OS security upgrades are resolved at build time, so production must promote the exact CI-built, scanned image digest; rebuilding from the same source is a new artifact and requires its own scan/runtime gates. No production image promotion or deployment has been executed here.

The scan gate also blocks High titles describing authentication/authorization or certificate-pinning bypasses, with negative policy regressions covering the actual Jetty and curl findings. Other High findings remain visible for review; this classifier supplements report review and does not replace it.
